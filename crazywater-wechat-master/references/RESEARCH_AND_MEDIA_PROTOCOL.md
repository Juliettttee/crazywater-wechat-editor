# Universal research-first, media-completeness, and text-image reconciliation protocol (v5.6)

Applies to completed-form, guided, drafting, revision, review, export, Codex and DeepSeek/Doubao. These are **mandatory gates**, not optional advice.

## Research
Read already provided files and user-confirmed constraints before looking up public facts. When web access exists and user allows it, search trustworthy public official project/developer, architecture/landscape consultant and government sources first; ask only for crucial missing, contradictory or uncertain information. Clearly identify public-source versus internal facts; no guessed company roles or technical specs. If no web access or opted out, mark the verification gap honestly.

## Image intake
- For each image, actually inspect it. Record exact original filename, media ID, type (on-site photo, rendering, construction, historical or unknown), visible water elements, context, possible intended chapter and confidence. Keep unknowns unknown; no fabricated water type, engineering specifications or video frames.
- On every batch, ask whether **all** intended images have been uploaded. Say “目前收到 N 张图片，这些是全部拟用于公众号的图片吗？” If not, ask total and ability to send more. Wait where user will send more; if can't, ask whether they approve a clearly marked provisional version.
- Confirm completeness even when received count equals expected count. Never presume that four photographs represent full assets.
- Videos are a separate collection; video planned but not provided gets a standalone {视频} marker.

## Mandatory second pass once photos complete
1. Analyse the full image set with the confirmed project form and design documents.
2. Compare each proposed textual claim, heading, technical description, image caption and visual storyline against objective content of each photo.
3. **Change the writing to match the images**: rewrite misleading, unsupported, overly generic or incomplete descriptions; reorder/adjust chapter emphases; swap or discard mismatched captions; identify unillustrated concepts and request missing supporting images if necessary.
4. Never infer concealed equipment, project authorship, flow calculations or control systems from photos. Resolve conflict between verified project documents and appearances by asking.
5. Keep user-approved style, length, scope and locked factual details unless evidence requires a proposed revision. Document major revisions in an editor-only change log.
6. Final publication-order Word/HTML may be produced only after these steps, or when user explicitly approves an incomplete-set provisional deliverable.
7. If supplementary photos arrive later, rerun the second pass on affected sections; don't reset the whole confirmed project.

## Output
Maintain claim→source→verification→permission ledger and per-photo status, and separate publishable text from editorial notes. Any question round at most 3 important questions. Mark factual unknowns and uncertainties for user resolution.
